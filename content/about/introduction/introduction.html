概説

この ARIA Authoring Practices Guide (APG) の概説では、APG の目的、前提とする知識、及び構成について説明します。

APG の目的

APG は、支援技術やキーボードインタフェースに依存する人々のためのウェブ体験を開発するためのガイダンスとして、複数のアクセシビリティ及びウェブ技術仕様の要件を統合しています。 APG には、アクセシブルなユーザインタフェースパターンのライブラリ、パターンの実装例、及び以下の方法を説明するガイダンスセクションが含まれます:

  • Accessible Rich Internet Application (ARIA) 仕様の機能を HTML、CSS、JavaScript、及びほかのウェブ技術と組み合せて使用することで、 一般的なユーザインタフェースパターンをアクセシブルにする。
  • ARIA、HTML、及び CSS を使用して、アクセシブルな名前 (name) の提供、キーボード操作の有効化、支援技術へのページ構造の伝達、ハイコントラストのオペレーティングシステム設定のサポートなど、基本的なアクセシビリティの実践を実装する。

APG の第一の目的は、以下のようなウェブアクセシビリティの実践に対する幅広い理解を構築し、採用を促進することで、堅牢でアクセシブルな体験の利用可能性を高めることです:

  • ARIA、HTML、CSS、及び関連仕様の意図と一致していること。
  • ARIA and Assistive Technologies Project によって評価される、支援技術の相互運用性をサポートしていること。
  • 障害のある人々のユーザビリティをサポートし、WCAG 要件に適合する現代的な GUI を開発するための実践的な技術を促進していること。

APG は規範的な標準ではない

APG のアクセシビリティガイダンスは、WCAG 及び ARIA で規定されたアクセシビリティ要件とは異なります。 WCAG 及び ARIA は W3C の規範的な技術標準であるのに対し、APG は参考リソースです。 正式には「W3C 勧告」として知られる W3C の規範的な技術標準は、標準に文書化された要件に適合する方法を定義する適合モデルを持っています。 これらの要件は、 W3C 勧告トラックによって定義された厳格なプロセスを使用して策定されます。

APG は規範的な要件を規定しておらず、したがって適合モデルを持っていません。 ARIA ワーキンググループの一部である ARIA Authoring Practices タスクフォースは、 APG ガイダンスが ARIA を含むすべての関連仕様と一致することを確保するために合意形成を使用しますが、そのプロセスは W3C 勧告トラックプロセスに拘束されません。

APG のガイダンスの一部は、規範的な仕様でカバーされていません。 たとえば、パターンには、ARIA で規定された規範的な要件と、一般的なオペレーティングシステムやソフトウェアによって確立された慣習を組み合せたキーボード操作モデルが含まれています。 フォーカスの管理のセクションでは、ARIA は Tab キーが特定の種類のウィジェット内でフォーカスを移動してはならないと規定する文言を含んでいます。 しかし、ARIA は特定のキーがこれらのウィジェット内でどのようにフォーカスを移動するべきかを規定していません。 そのため、APG タスクフォースは、ナビゲーション及び操作のためのキーボードコマンドのリストを各パターンに提供するために、広く利用されているキーボード慣習に依存しています。 これらのリストは規範的ではありませんが、そのような慣習の大部分は十分に確立されているため、要件として扱うことが望ましいです。 そうでない場合、ガイダンスはオプションとして明確にマークされています。 なお、ウェブウィジェットが利用者のオペレーティングシステムの慣習を動的に反映するように調整すれば、利用者により良いサービスを提供できるキーボードコマンドがいくつかあることに注意してください。 一部の APG キーボード操作モデルが macOS 固有のガイダンスをまだ十分に提供していないことは既知の課題です。

APG パターンから逸脱する場合は注意

APG は標準ではありませんが、そのパターン及び実践は規範的な標準からの要件を伝えています。 コンテンツ制作者が幅広い UI デザインニーズに対応できるように、パターン及び実践は、これらの標準を満たす可能性の範囲とオプションを説明しています。 例はそれぞれ、1 つ以上のパターンを実装する特定の方法を表しています。これらは例示的であることを意図しており、規定的ではありません。

しかし、APG パターンライブラリは、アクセシブルなユーザインタフェースを構築するための可能で、有効で、潜在的に使用可能なすべての方法のカタログとして機能することを意図していないことを理解することが重要です。 したがって、一部の開発者は、UI 要件をサポートする体験を作成するために、様々な APG パターンを単に組み合せるだけでは不十分だと感じる場合があります。 APG パターンから逸脱する UI を構築する場合は、UI のデザイン及び動作が以下を確保してください:

  • APG 実践でカバーされている関連ガイダンスと一致していること。
  • ARIA 仕様の規範的な要件に準拠していること。
  • 類似の APG パターン又はネイティブオペレーティングシステムウィジェットのキーボード慣習に従うか、模倣していること。

APG は UI デザインシステムではない

APG はパターンのライブラリと機能的な例を含んでいますが、その目的は包括的なデザインシステムや本番環境対応のコードを提供することを含んでいません。 本番環境対応のデザインシステムを開発することは Authoring Practices タスクフォースの能力を超えるだけでなく、統一されたデザインシステムの要件を満たす例を開発することは、関連する実践の幅広い理解を構築するという第一の目的を妨げることになります。 APG の例は、コードスタイルを含め、それらが説明するアクセシビリティの概念を学ぶことを容易にするように設計されています。 設計への様々なアプローチがアクセシビリティ要件をどのように満たすことができるかを示すために、例のスタイル及び動作は意図的に互いに一貫性がない場合があります。 更に、例は合理的に現実的で現代的なコーディング技術を利用することを意図していますが、その目的は、ローカライゼーションや堅牢なプラットフォーム相互運用性など、ウェブエンジニアリングのほかの側面を教えることではありません。 プラットフォーム及びブラウザサポートに関する詳細情報は、 最初にお読みくださいで伝えられています。

重要な前提知識

APG タスクフォースは、可能な限り平易でシンプルな言葉を使用することで、APG を幅広い読者に歓迎されるものにするよう努めています。 そのため、ウェブ開発やアクセシビリティについて最小限の理解しかない読者でも、キーボード操作パターンなど、ガイダンスのかなりの部分から恩恵を受けることができます。 同時に、APG で扱われている多くのトピックは本質的に複雑であり、技術的に正確な用語を必要とします。 更に、アクセシブルな体験を作成する上での重要な側面の一部は、APG の範囲外です。 このセクションでは、読者が APG から最大限の恩恵を得ることを可能にする可能性のある前提知識の種類とサポートリソースについて説明します。

大まかに言えば、APG はアクセシビリティ、UI デザイン、及びウェブエンジニアリングを融合しています。 APG をうまく活用するために、読者が 3 つの分野すべてで実務知識を持つ必要はありません。 アクセシビリティ専門家は、少なくとも HTML 及び CSS の基本的な理解があれば、APG がより有益であることがわかるでしょう。一方、デザイナー及びエンジニアは、いくつかのアクセシビリティの基礎に精通している必要があります。 すべての読者は、いくつかの基本的な ARIA の概念をしっかりと把握する必要があります。

ウェブデザインやエンジニアリングを理解しているが、アクセシビリティや支援技術に精通していない人々は、パターン及び例のコードによって提供されるガイダンスの多くを実装できる可能性があります。 しかし、ガイダンスの多くの側面は規定的でも包括的でもないため、読者は障害のある利用者に影響を与える可能性のあるトレードオフを評価する必要がある決定を下す必要がある場合があります。 障害のある人々のニーズと、それらを満たす上での支援技術の役割についてある程度理解することに加えて、開発者がいくつかのテストを実行できることが不可欠です。 アクセシビリティ及び支援技術の理解を深めるための関連リソースには以下が含まれます:

  • WAI Accessibility Fundamentals
  • WAI Overview of Design and Development

アクセシビリティ及び支援技術に十分に精通している読者は、ARIA の目的とアクセシビリティセマンティクスが何であるかについての理解も必要とします。 これらのトピックは ARIA の基本でカバーされています。

APG の構成

APG は以下の主要セクションに構成されています。 APG 全体のいくつかの場所でアドバイスされているように、パターンや実践を利用する前に、 最初にお読みください で提示されている情報を理解することが重要であることに注意してください。

セクション 説明
パターン 典型的なボタンやポップアップメニューから複雑なツリーグリッドまで、30 を超える一般的なユーザインタフェースパターンのライブラリです。 各パターンは、その目的、キーボード操作モデル、アクセシビリティセマンティクスを説明し、1 つ以上の説明的な機能実装例によって補完されています。
実践 アクセシブルな名前 (name) の提供、キーボード操作の有効化、支援技術へのページ構造の伝達、ハイコントラストのオペレーティングシステム設定のサポートなど、リッチインターネットアプリケーション体験をアクセシブルにする際に生じる様々なアクセシビリティニーズを満たす方法についての詳細な説明を提供します。 たとえば、アクセシブルな名前 (name) と説明の提供に関する実践セクションでは、7 つの異なる命名技術の詳細な説明と、80 を超えるタイプの要素の命名に関するガイダンスを提供する表が含まれています。
索引 ARIA ロール、ステート、及びプロパティ別にリストされた例など、パターンの実装例の複数の索引を提供します。
APG について 概説、謝辞、カバレッジ及び品質レポートなど、APG に関する情報を提供します。
